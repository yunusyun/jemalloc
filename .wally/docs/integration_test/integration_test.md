# Integration testing

## Sources and runner

Derived from `Makefile.in` (`tests` target, line 529; `check` target, line 553), `test/test.sh.in`, `scripts/gen_run_tests.py` and the CI configs. Integration tests are executed through the `test/test.sh` harness. The canonical entry point is:

    make tests && make check

`make check` runs `check_unit`, `check_integration`, `check_integration_decay` and `check_integration_prof`. CI confirms the same sequence: `.travis.yml` (`make -j3 tests` then `make check`), `.cirrus.yml` (`gmake tests` then `gmake check`), `.appveyor.yml` (`mingw32-make tests` then `mingw32-make -k check`).

## Environment and preparation

Local source build tree. From the repository root: `./autogen.sh` (or `autoconf` followed by `./configure`), then `make tests && make check`. No external services, test data or credentials are required. A broader compiler/config matrix is generated by `scripts/gen_run_tests.py` via `run_tests.sh`, but note that the generator uses Python 2 syntax and `run_tests.sh` is malformed; treat `make check` as the real entry point.

## Assertions and result criteria

`test/test.sh.in` defines pass=0, skip=1, fail=2, and the harness exits 0 only when `fail_count` is 0. On completion it prints:

    Test suite summary: pass: <p>/<total>, skip: <s>/<total>, fail: <f>/<total>

## Success criteria (readiness: ready)

`make check` exits 0 and the summary shows `fail: 0/<total>`. Empty or all-skipped runs are not passes. Distinguish assertion, environment and execution errors. Evidence: captured `make check` stdout containing the summary line.

## Cleanup

`make distclean` / `make relclean` remove build artifacts (see `INSTALL.md`).
